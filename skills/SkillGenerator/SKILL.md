# SkillGenerator – AgentBee 任务技能与工具能力生成器

## 定位

将业务目标转成 Agent 可执行、可复用、可验证的任务能力。首要产物是 `SKILL.md`：说明何时处理、收集什么信息、如何推进、何时确认、如何验收。工具只是实现任务的一种手段，不是技能的必需组成。

按需求选择一种交付形态：

- **任务引导型标准技能**：固化流程、分析方法、判断规则、协作方式、输出和验收；可不使用工具。
- **工具集成型技能**：在任务流程中编排已有 AgentBee 工具、系统工具、外部命令、API 或已授权服务；重点是准确调用和异常处理。
- **AgentBee 内部工具模块**：仅在已有能力和可用外部工具均不能满足需求、且用户确认需要稳定复用时创建。

目标不是增加文档或工具数量，而是让 Agent 能可靠完成目标任务。

## 总原则

### 先定义任务，再决定能力形态

先明确目标、业务规则和完成标准，再盘点可复用能力。不得为了形式强行增加工具或内部模块。

- 流程、规范、分析、决策、质量控制或已有能力组合有复用价值时，优先创建任务引导型标准技能。
- 需要执行能力时，优先复用已有专项技能、内部工具、系统工具或外部工具。
- 只有复用和外部工具均不可行，且用户确认新能力具备稳定、重复、独立调用价值时，才新建内部工具模块。
- 不得虚构工具、依赖、命令、接口、路径、权限或系统能力。

### 工具来源不预设实现方式

工具可能是 AgentBee 内部工具、系统工具、外部命令、API 或其他已授权服务。必须按真实文档或用户提供的规范描述调用；不得把内部工具样板强加给外部工具。

### 信息充分则推进，关键不确定则确认

信息足以确定边界时直接完成，不要为形式重复追问。以下不明确且会影响安全、成本、权限、数据、架构或结果时，必须确认：

- 产物形态或工具来源无法判断；
- 覆盖、删除、批量写入、外发、上传、通知、扣费等副作用；
- 外部服务的认证、数据范围、频率或费用限制；
- 关键输入、成功标准、输出冲突策略或调用边界。

可采用安全默认值的事项，直接推进，并在交付中说明假设。

### 安全与规则优先级

冲突按以下顺序处理：

1. 系统安全限制和平台规范；
2. 用户明确授权和业务要求；
3. 兼容性、数据保护与回滚要求；
4. 用户提供的模板、接口、样例和参考规范；
5. 本技能默认规则；
6. 示例和历史习惯。

冲突可能造成安全、数据或兼容性损失时，停止高风险动作，说明差异、影响和选项，等待确认。

凭据只能经环境变量或用户授权的安全配置传入，不得写入代码、示例、日志或错误信息。文件操作限于工作区或授权目录；覆盖、删除、批量写入和对外发送前必须确认。外部调用必须有超时、错误处理和可解释的失败结果。

## 产物判定与能力盘点

开始时先输出简洁判定：

```text
产物类型：任务引导型标准技能 / 工具集成型技能 / AgentBee 内部工具模块 / 不创建技能
判定理由：
任务目标与完成标准：
工具来源：无 / AgentBee 内部 / 系统已有 / 外部工具 / 待确认
复用能力：
新增能力边界：
```

| 需求特征 | 推荐产物 |
|---|---|
| 固化流程、规范、分析框架、判断逻辑、输出或质量标准 | 任务引导型标准技能 |
| 编排多个已有技能或工具 | 工具集成型技能 |
| 使用已有外部命令、API 或服务 | 工具集成型技能，写明真实调用引导 |
| 现有和外部能力均不足，且用户确认开发稳定新能力 | AgentBee 内部工具模块；如该工具需要任务工作流，再同级增加 `SKILL.md` |
| 一次性任务，无复用价值 | 不创建技能，直接完成任务或给方案 |

### 能力盘点

能力盘点先于任务设计和内部工具模块设计，不得凭名称猜测能力。按以下优先级核实：

1. 当前系统声明的专项技能和可调用工具；
2. 技能目录中的实际文件和模块定义；
3. 用户指定的参考技能、目录、工具或文档；
4. 已加载技能的说明和能力声明；
5. 无法确认的内容标记“待确认”。

执行步骤：列出现有能力，读取候选能力的真实说明，判断“直接满足 / 组合满足 / 不足”，输出复用矩阵；现有能力不足时先评估外部工具集成，仅在外部工具也不适用且用户确认后才评估内部模块。

```text
| 用户需求 | 候选能力 | 覆盖程度 | 结论 |
|---|---|---|---|
| 读取表格 | 已有表格能力 | 完整覆盖 | 直接复用 |
| 调用专有 API | 无 | 不覆盖 | 评估外部集成或内部模块 |
| 输出报告 | 已有文档能力 | 完整覆盖 | 编排调用 |
```

同时识别目标用户和场景、输入输出、判断节点、触发词、数据敏感性、权限、外发和覆盖风险、参考资料及替代方案。

## 设计

### 参考提取

用户提供参考技能、样例、模板或目录时，先读取并提炼，再设计；不得照抄或仅凭印象改写。记录有效的结构、命名、字段、能力边界、调用方式、配置、错误处理、测试方式，以及应继承或不应复制的规则。

### 标准技能最低内容

每份 `SKILL.md` 至少包含：

1. YAML：`name`、`description`、`triggers`、`version`；
2. 定位、适用场景和非适用场景；
3. 输入、输出、默认项和用户确认条件；
4. 可执行步骤、分支、完成条件和失败处理；
5. 与已有能力的协作或调用顺序（如需要）；
6. 数据、安全、内容边界和人工介入点；
7. 验收和交付说明。

`description` 用一句话说明价值、处理对象和产出。`triggers` 覆盖真实的中英文及常见口语表达，但不得泛化到无关任务。YAML `name` 与目录名一致；一级标题以 YAML `name` 开头，可追加说明副标题。

任务引导型和工具集成型技能可沿用既有名称风格。工具集成型技能必须写清真实调用引导、前置条件、结果识别和失败处理。仅内部工具模块遵循下文的模块规范。

### 工具调用引导

技能使用工具时，每个关键调用按已确认文档或授权说明以下内容：

```text
当前步骤需要执行：[工具或能力]
调用方式：[工具调用、命令、API 操作或执行说明]
输入：[必要输入]
预期输出：[结果或产物]
失败处理：[重试、降级、停止或转人工]
```

还应说明权限、配置、超时、费用、幂等性、确认点和副作用。不得虚构命令、接口、参数、方法名或内部实现。已有内部工具和外部工具遵循其真实返回约定；新建内部工具遵循下文返回规则。失败信息不得泄露密钥、隐私、完整内部路径或堆栈细节。

### 需求追溯与设计冻结

复杂、多步骤、高风险、工具协作或含 P0/P1 需求的技能，必须建立完整追溯矩阵：

```text
| 编号 | 优先级 | 需求 | 规则/实现位置 | 验收方式 | 状态 |
|---|---|---|---|---|---|
| R1 | P0 | 核心任务 | 工作流 | 合法样例验证 | 已实现待验证 |
```

优先级仅为 `P0`（必须）、`P1`（重要）、`P2`（可选）；状态仅为“已验证、已实现待验证、待用户确认、不适用、未实现”。P0 未达到“已验证”或“不适用”时，不得评为 A。

简单、低风险、单一目标任务可用“需求—规则—验收”简表替代矩阵，但必须列出目标、关键规则、验收标准和未覆盖项。

写入正式文件前，冻结产物类型、名称、版本、任务流程、输入输出、工具调用边界、确认点、安全边界、依赖、配置和测试方案。实质变化时先分析对调用约定、默认行为、权限、文档、配置、实现、测试和版本的影响，再同步更新受影响内容；不得造成记录不一致。

## AgentBee 内部工具模块开发规范

### 适用边界

本节只适用于**确认新建 AgentBee 内部工具模块**。外部命令、第三方 API、网页服务和已有系统工具不得套用本节结构。

开始前必须确认：现有能力和可用外部工具均不满足；新能力具有稳定复用价值；工具名称、输入输出、权限、配置、数据范围、副作用和验收标准已冻结。

`examples/Calculator/` 是同步内部工具的三文件最小参考样板，只演示 `go.php`、`skills.php`、`module.json` 的工具实现契约；它本身可作为纯工具被加载。只有该工具还需要任务工作流、触发词与调用编排时，才在同级增加 `SKILL.md`，形成技能含工具。`ImageMaker` 展示了带配置、跨进程转发和流式回传的特殊实现；不得把其异步结构当作普通工具默认方案。

### 固定文件与命名

每个可被 AgentBee 扫描、加载的单元，必须位于 `skills/` 下的独立一级目录。根据能力形态，以下三种结构均合法；除列出的主文件外，其他文件只能按本规范的适用条件增加：

```text
# 纯技能：仅提供任务引导
[SkillName]/
  SKILL.md

# 纯工具：仅提供可调用能力
[ToolName]/
  go.php
  skills.php
  module.json

# 技能含工具：由 SKILL.md 编排同级内部工具
[SkillName]/
  SKILL.md
  go.php
  skills.php
  module.json
```

纯技能不得伪造工具文件；纯工具不得要求 `SKILL.md`；技能含工具时四个主文件必须同级齐全。`examples/Calculator/` 是本技能内部的纯工具参考样板，不是 `skills/` 下的正式加载单元。

- **三值合一**：目录名、`module.json.name`、PHP 命名空间中的模块名必须完全一致，且严格区分大小写；三者任意一个不同，模块即不完整，不得交付或加载。
- `module.json.entry` 必须指向实际存在的入口文件，默认且通常为 `go.php`。
- `go.php` 定义 `go` 类，继承框架规定的基础类；`skills.php` 定义 `skills` 类，并提供 `public const META`。
- `skills.php` 声明的每个函数名，必须在 `go.php` 中存在同名的 `public` 方法。
- 声明和实现的参数名、数量、类型、必填性、默认值、取值范围和返回说明必须一致。
- 描述只能声明已经实现的能力；不得把规划功能、内部类或未配置能力暴露给 LLM。

`module.json` 至少真实包含名称、版本、描述、作者、入口、依赖和 PHP 运行要求。仅在确有配置前置条件时添加 `config` 字段。

### 同步优先与代码分层

普通内部工具必须同步执行。`go.php` 是唯一的 LLM 调用入口，负责：接收参数、执行必要校验、调用业务逻辑、整理并直接返回结果。

```text
LLM → skills.php 的 META 声明 → go.php 的 public 方法 → 返回结果
```

业务简单时，逻辑直接放在 `go.php`。同步业务复杂时可增加 `lib/` 分离服务、协议封装、数据转换或可复用逻辑：

```text
[SkillName]/
  SKILL.md
  go.php
  skills.php
  module.json
  lib/
    XxxService.php
```

此时 `go.php` 仍是唯一公开入口；`lib/` 不得直接向 LLM 暴露方法。

仅在确有跨进程调度、异步任务、流式消息回传或框架明确要求时，才可增加 `handler.php` 或同类文件。此类实现必须说明：为什么同步不适用、调度数据如何传递、最终结果如何回收、超时和失败如何处理。不得为普通网络请求或普通计算虚设异步结构。

### 配置与加载门禁

无配置依赖的工具不应添加 `config` 字段。

如果 `module.json` 声明：

```json
"config": "ToolName.json"
```

该配置文件就是工具的**加载前置条件**，不是可选备注。必须同时满足：

1. Agent 实际配置目录中存在同名文件，例如 `AgentBee/config/ToolName.json`；
2. 文件可解析，且必填项完整、值有效；
3. 模块内提供脱敏模板 `config/ToolName.json`；
4. 模块内提供 `config/README.md`，写明复制目标、字段说明、必填项、获取方式和缺失后果；
5. `go.php` 或其调用链在执行前校验所需配置，并返回不泄密的可操作错误。

缺少、无效或必填项不完整时，工具不得被加载、暴露给 LLM 或执行。模板只能使用占位值；密钥、令牌、真实账号、内网地址和用户数据不得写入模块目录、`SKILL.md`、样例、日志或错误信息。

允许采用其他配置机制，但必须在 `module.json`、实现和部署说明中明确配置来源、加载条件、字段校验和安全边界；不得让 LLM 猜测配置位置或字段。

### 能力声明与输入校验

`skills.php` 的 `META` 是 LLM 的调用契约。每项能力必须写明准确的名称、用途、参数类型、必填参数、默认值、范围和关键限制。名称应使用动词或清晰动作，不得使用含糊词。

`go.php` 不得只依赖 LLM 声明。对路径、数量、枚举、格式、权限、文件可读性、数据范围和副作用，必须在执行侧再次校验。涉及文件、网络、费用、外发或修改操作时，应在实现中落实授权范围、超时、错误处理和幂等或重复执行策略。

### 返回与错误约定

新模块成功时统一返回：

```php
[
    'status'  => 'success',
    'message' => '面向调用方的简短结果说明。',
    'data'    => [/* 结构化业务结果 */],
]
```

失败时统一返回：

```php
[
    'status' => 'error',
    'error'  => '可行动、无敏感信息的失败说明。',
]
```

`data` 可包含单值、列表、文件信息或统计结果；字段语义必须稳定，并在 `skills.php` 描述中说明。不得对新模块使用孤立的 `result` 作为标准顶层字段。兼容、维护既有工具时，以其已有真实约定为准，除非用户明确要求迁移。

不得在返回值中暴露密钥、完整堆栈、未经授权的完整路径、原始服务响应或个人敏感信息。异常必须转换为可判断的错误结果；未知失败不得伪装成功。

### 开发顺序

1. 写明能力边界、输入输出、权限、副作用、配置和验收标准；
2. 以 `examples/Calculator/` 创建工具三文件骨架；仅当该工具需要任务工作流、触发词或调用编排时，才在同级新增 `SKILL.md`，形成技能含工具；
3. 先完成 `skills.php` 调用契约，再实现 `go.php` 同名公开方法；
4. 复杂同步逻辑再抽入 `lib/`；只有满足特殊条件才设计异步处理器；
5. 如需配置，先提供脱敏模板与说明，并验证 Agent 实际配置目录的有效配置；
6. 完成发现、加载、调用、成功、失败和边界验证；
7. 将真实调用方式、配置前置条件和未验证项写入配套 `SKILL.md` 或交付说明。

## 生成与目录处理

使用 UTF-8 编写 Markdown、YAML、PHP 和 JSON。关键约束使用“必须/不得”，建议使用“优先/建议”；避免用“视情况、尽量、适当”代替判断条件。

- **无工具任务**：通常只生成 `SKILL.md`、模板、检查清单或用户要求的交付物。
- **已有或外部工具集成**：通常在 `SKILL.md` 中记录调用引导和限制；仅在必要时附示例、配置说明或测试计划。
- **内部工具模块**：仅在已确认后，按本规范生成实现、能力声明、元数据、测试和必要配置。

默认写入系统定义的 `skills/`。每个可加载的技能或工具单元都是 `skills/` 下的一个一级目录；该目录是唯一可加载单元。写入前确认名称与目录一致；目标已存在时先读取，不得直接覆盖。修改已有技能时，只修改用户授权范围，并先创建带版本或时间戳的备份；验证失败立即恢复。未经授权不得删除已有文件。批量创建或修改多个技能时，先列清单让用户确认。

### 技能与工具存放层级

`skills/` 下的一级子目录是唯一加载单元。纯技能只需 `SKILL.md`；纯工具只需 `go.php`、`skills.php`、`module.json`；技能含工具时，`SKILL.md` 必须与三个工具文件在同一一级目录并列。不得把一个技能的工具拆到另一个一级目录，也不得放入二级或更深目录。

```text
skills/
  [GuideSkill]/                 # 纯技能
    SKILL.md
  [ToolName]/                   # 纯工具
    go.php
    skills.php
    module.json
  [SkillWithTool]/              # 技能含工具
    SKILL.md
    go.php
    skills.php
    module.json
```

- 含 `SKILL.md` 的目录名必须与 YAML `name` 一致。
- 含工具文件时，目录名、`module.json.name` 和两个 PHP 文件命名空间中的模块名必须三值合一，严格区分大小写。
- 不得创建 `skills/[SkillName]/[ToolName]/`、`skills/category/[SkillName]/` 等嵌套技能或工具目录；框架无法保证发现和加载。
- `lib/`、`config/`、`examples/`、`tests/`、`scripts/` 可作为 `skills/[SkillName]/` 内的辅助目录，但不得包含另一套可加载的 `go.php`、`skills.php`、`module.json`，也不得形成独立加载单元。

选择“纯技能”“纯工具”“技能含工具”三种主文件结构之一后，再按需增加以下辅助目录；不得将该示意理解为纯工具必须包含 `SKILL.md`，也不得将其理解为纯技能必须包含三个工具文件：

```text
skills/[LoadedUnit]/
  lib/                               # 仅复杂同步工具按需创建
  config/                            # 仅 module.json 声明 config 时必需
  examples/                          # 按需；内部工具样板仅供内部模块参考
  tests/                             # 内部工具默认创建；外部集成按需创建
  scripts/                           # 可选
  CHANGELOG.md                       # 持续迭代时按需创建
```

## 验证、交付与等级

### 标准技能验证

交付前完成结构检查和至少两个桌面推演：一个常规成功场景，一个信息不足、冲突或失败场景。确认步骤有启动和完成条件，分支可闭环，不依赖未声明的工具、权限或文件，且规则之间无冲突。

门禁：

- YAML 可解析，包含必填字段；名称、目录和标题一致；
- 触发词、适用/非适用范围、输入输出、流程、异常处理、安全边界和验收标准完整；
- 引用的能力真实存在，或明确标为待配置；
- 文档无乱码、空字符、重复章节、矛盾规则和无效路径；
- 复杂或高风险技能的追溯矩阵完整；简单技能的“需求—规则—验收”简表完整；
- 推演记录保留用户请求、命中触发词、协作能力、关键步骤、预期输出、发现问题和修正结果。

### 工具能力验证

按实际形态验证：

- **无工具任务**：验证核心步骤、分支、确认点和验收标准；
- **已有或外部工具集成**：验证或如实记录调用前提、调用过程、输入输出、结果识别、权限、超时、费用和失败处理；
- **新建内部工具模块**：额外完成发现、加载、调用三层验证，以及成功和失败/边界测试。

内部工具模块三层验证只适用于纯工具与技能含工具；纯技能按“标准技能验证”执行，不要求工具发现或调用测试：

1. **发现**：模块目录是 `skills/` 下一级目录；纯工具有完整的 `go.php`、`skills.php`、`module.json`，技能含工具四文件并列齐全；不存在嵌套可加载模块。`module.json` 可解析，目录名、`module.json.name`、命名空间、入口和声明无冲突；如声明 `config`，Agent 配置目录中的同名配置有效。
2. **加载**：框架可扫描、加载模块并发现 `skills.php` 的能力声明；配置不满足时工具不应被暴露或执行。
3. **调用**：在隔离或模拟环境完成一次“能力发现 → 输入校验 → 执行 → 返回校验”的最小调用；每个声明能力至少有一次成功测试，并至少覆盖一个非法输入或边界场景。

对副作用能力不得使用生产环境。无法执行真实验证时，可做静态替代验证并记录原因、影响和后续条件；此时最高交付等级为 B。不得只写“已检查”或“待验证”。验证记录必须包含实际命令、工具或手工步骤、输入、预期结果和实际结果。

### 对抗审查

至少检查：空输入和格式错误、名称或目录冲突、配置缺失或格式错误、无权限或无凭据、网络失败和超时、限流或配额不足、文件覆盖和外部副作用、误触发或职责重叠、规则冲突和失败恢复。发现问题后修正，并复验受影响部分。

### 完成与交付

标准技能完成：文件落地；结构检查和桌面推演通过；P0/P1 已验证或明确不适用；未实现、待确认或待验证事项已列为风险，不得宣称完整可用。

工具能力完成：按实际产物形态满足对应门禁。纯技能通过结构检查和桌面推演；工具集成技能验证调用边界；纯内部工具通过三层验证和核心测试；技能含工具同时满足标准技能与内部工具两类门禁。仅完成规则、调用引导或设计，暂不实现时，交付等级为 C，不得伪造验证结论。

交付说明使用：

```text
产物类型：
技能名称与版本：
保存路径：
生成或修改文件：
复用能力与工具来源：
配置状态：无配置 / 已配置并验证 / 待用户配置
验证结果：
未验证、待配置或待确认事项：
后续使用方式：
交付等级：A / B / C
```

- **A**：所需端到端验证和核心测试通过，全部 P0 已验证，无未关闭高风险问题；
- **B**：结构、静态检查或模拟验证通过，但仍需凭据、权限、硬件、账号或真实环境联调；
- **C**：仅完成设计、规则、调用引导或骨架，尚不可投入使用。

不得将 B 或 C 标为 A。

本技能目录的 `examples/Calculator/` 是同步 AgentBee 内部工具实现样板，仅在确认新建内部工具模块时参考其三文件结构、调用契约、返回结构和验证要求。正式交付为纯工具时，放入 `skills/[ToolName]/` 并保留三文件即可；只有工具还需要任务引导时，才在同级补齐 `SKILL.md`，组成四个主文件。涉及配置、跨进程、异步或流式回传时，可阅读已有 `ImageMaker` 的实际实现来识别特殊要求；不得复制其异步结构，除非需求确实满足其适用条件。
